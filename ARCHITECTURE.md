# Architecture

Two public parts: the linter (`arkui-sem/`) and the demo project where agents use it (`sandbox/demo/`). The bench that
measures the linter on masked real code is the private submodule `bench/` (its `README.md` has its layout). Docs are
in `docs/` (map: `AGENTS.md`).

## How the linter works

```
.ets edit ──► fact extractor ──► rule candidates ──► slice + question ──► System One judge ──► p
 (agent tool)   (analysis.ts)      R1 / R3 (R2 planned)   (judge.ts)          (Jev, Clef, ...)      │
                                                                                                    ▼
                         agent feedback ◄── findings (p ≥ 0.8) / questions (0.5 ≤ p < 0.8)  (engine.ts)
```

The opencode plugin runs this after each edit tool call, gates the session once on idle while findings remain, and
gives the agent `arkui_check` and `arkui_facts`. The skill `arkui-state-management` teaches the agent the decorators.

## Layout

```
README.md, AGENTS.md, CLAUDE.md (@AGENTS.md), CONTRIBUTING.md, ARCHITECTURE.md
.gitignore, .gitattributes                LF line endings everywhere; ignores refs/, sandbox scratch, the local setup notes
docs/                                    see AGENTS.md for the map
scripts/setup.mjs [--doctor]             build the linter, install the plugin into sandbox/demo, enable .githooks; runs bench/setup.mjs when present
.githooks/pre-commit                     Biome check of staged arkui-sem/ files, typecheck when TypeScript is staged
.github/workflows/test.yml               CI: npm ci + npm run lint + npm test in arkui-sem/ on Linux, every PR and push to main
.github/pull_request_template.md         PR description: what and why, how it was checked, notes
.claude/settings.json, opencode.json,    deny rules for the key file and `arkui-sem config`
.codex/rules/arkui-sem.rules               (Codex: exact command prefixes; test with `codex execpolicy check`)
.gitmodules                              bench → ../arkui-sem-bench.git (private; relative to this repo's URL)
bench/                                   private submodule: datasets, runs, results, eval scripts, evaluation docs
refs/arkeval/                            ArkEval v1/v2 paper text (pdftotext; git-ignored)
sandbox/demo/                            the demo project (opencode): R1 pages in entry/src/main/ets/pages/ (Profile: nested write,
                                           Counter, Feed, Toast: undecorated mutated field) + DEMO.md; .opencode/ is generated by setup
sandbox/*                                everything else is local scratch (ignored), e.g. a DevEco Code copy of the demo
arkui-sem/                               the linter (opencode plugin, package arkui-sem 0.2.0, ESM, TypeScript)
  README.md, AGENTS.md
  src/opencode.ts      plugin: tool.execute.after feedback, session.idle gate, tools arkui_check / arkui_facts
  src/analysis.ts      fact types, .ets discovery, naive fact extractor (stand-in for ArkAnalyzer + APAK),
                       rules R1 undecorated-mutated-rendered, R1 nested-write-unobserved (depth-aware), R3 unreleased-resource
  src/judge.ts         System One interface, Jev, Clef, answer helpers, questions (Q_R1/Q_R2/Q_R3), slices (SPEC_CARDS),
                       heuristic, DeepSeek (flash, structured output), backend registry
  src/engine.ts        candidates → slices → judge → finding/question bands (thresholds 0.8 / 0.5); agent formatting
  src/config.ts        defaults < ~/.config/arkui-sem/config.json < .opencode/arkui-sem.json < env < plugin options
  src/cli.ts           arkui-sem check | config | lsp  (default backend: clef)
  src/lsp/             utility client for ace-server (ArkTS language server): definition, references, call hierarchy
  test/arkui-sem.test.mjs  all tests (npm test, offline); test/fixtures/: Counter, Feed, Profile (R1), Ticker (R3),
                       fake-ace-server.mjs (both LSP protocols)
  skills/arkui-state-management/SKILL.md, scripts/install.mjs
  backends `or-clef` / `or-clef-flash`: Clef via OpenRouter Decisions API (POST https://openrouter.ai/api/alpha/decisions; OPENROUTER_API_KEY or openrouter.apiKey; openrouter.baseUrl)
  backend `laya`: local TypeSafe-compatible server (default http://127.0.0.1:8080; laya.baseUrl / LAYA_BASE_URL);
    state limit ~424 tokens, so slices are trimmed on 422; zero-shot it scores the fixture bugs 0.13–0.27 (unusable before fine-tuning)
```
